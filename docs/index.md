## Code

All code used in the project exists in `.py` files in the top level of the project repository. ***Most are
not intended to be run by other users.*** There are two exceptions:
- `demo.py`: Pipeline of the demo described in [the README](../README.md). Performs the following
  steps:
  - Creates the `demo_files` directory and sub-directories necessary for organizing generated files
  - Loads training corpus from the compressed `mention_corpus.cor.bz2` file
  - Trains Word2Vec embeddings on corpus
  - Clusters embeddings (w/ visuals)
  - Plots player similarity vs. stats graphs as described in [Results](#results) below
  - Creates tensor and metadata files necessary for use in the public TensorBoard Projector
    (for replicating my embedding visualization, if so desired)
- `database_import.py`: Extracts and builds the `war_db` SQLite database from the `war_db.db.txt.bz2`
  file in `data`. More info on the database can be found in [Data](#data) below. To use, run 
  `python database_import.py` or `python -m database_import` from the command line, as with the demo.

The files *not* intended to be run by users include:
- `clustering.py`: Methods for clustering embeddings, tuning cluster hyperparameters, and recording and
  visualizing cluster data.
- `data_downloader.py`: Methods for constructing SQL tables and organizing initial data, downloading articles,
  removing articles, and parsing HTML.
- `embeddings.py`: Methods for training Word2Vec embeddings, performing grid search, and computing embedding
  similarity. Custom `DataCorpus` and `LossCallback` classes for use in embedding training.
- `stat_plots.py`: Methods for retrieving and calculating player statistics, as well as plotting graphs
  involving player statistics.
- `text_processing.py`: Methods for cleaning article text, replacing mentions, and organizing player 
  and mention data.
- `utils.py`: Widely reused global variables, such as file paths and the random seed, as well as a custom
  context manager-based function based on `os.chdir`.

These files do not have active main methods and generally consist of collections of methods run
in different combinations at various stages of the project, often with active changes during use
(particularly with article downloading and processing methods). Depending on when I last used them,
their file paths and overall construction may be more or less dysfunctional. ***Use at your own risk.***

## Data

The [`data`](../data) directory contains data files necessary for running the project code:
- `mention_corpus.cor.bz2`: A compressed version of the corpus used in the main experiment.
- `player_list.txt`: List of player IDs for the main player set.
- `player_nationality.tsv`: List of player IDs with player nationality.
- `regex_dict.jsonl`: JSONL file containing a dictionary for each player mapping their player ID to
  a full name, first name, and last name target strings. Automatically compiled from BRef data with
  some manual correction to account for alternate names.
- `target_words.json`: Dictionary of interest word categories and their respective word lists.
- `team_names.json`: Dictionary of team names and abbreviations to be used in regex for masking team mentions.
- `war_db.db.txt.bz2`: A compressed version of a SQLite database containing relevant info tables, including
  an article ID-player ID mapping table, an article metadata table, and information on all players in the 
  main player set (among other info).
- `mentions`: Records of player mentions generated by `replace_mentions` in `text_processing.py`.
  - `article_mentions.json`: List of article IDs with number of total mentions.
  - `article_players.json`: Dictionary of article IDs with lists of players appearing in each article.
  - `player_mentions.json`: Dictionary of player IDs, each with a dictionary mapping article IDs to
    the number of mentions of the given player in each article.
- `stats`: Player statistics pulled from Baseball Reference database and generated by `get_pitcher_stats`,
  `get_batter_stats`, `calc_pitcher_stats`, and `calc_batter_stats` in `stat_plots.py`. For descriptions
  of their contents, see [Statistics](statistics.md).

## Results

The [`results`](../results) directory contains files generated in the process of conducting the
project's main experiment:
- `LOGGER_dim-300_lr-0.025_window-10_neg-5_ep-3_sample-1e-05.log`: Logger events from Word2Vec model training.
- `LOSS_dim-300_lr-0.025_window-10_neg-5_ep-3_sample-1e-05.log`: Loss per epoch computed during Word2Vec training.
- `w2v_dim-300_lr-0.025_window-10_neg-5_ep-3_sample-1e-05.model`: Word2Vec model from main experiments saved after training.
- `clusters`: File records related to embedding clusters generated by `cluster_embeddings` and `get_cluster_stats`
  in `clustering.py`.
  - `cluster_graphs.png`: Graph of silhouette scores for each cluster and scatter plot of entity embeddings
    for both clustering methods.
  - `members_{method}.json`: List of clusters and members from the given method.
  - `members_{method}_stats.csv`: Records of player IDs with associated cluster number, nationality,
    primary position, and primary team.
- `figs`: Image files of similarity plots generated by `plot_stats` and `compare_war` in `stat_plots.py`.
  - `{word}_vs_{stats}.png`: Graph of cosine similarity between given word and all relevant entities
    vs. relevant statistics drawn from the files in `data/stats`.
  - `{position}_vs_{player}.png`: Graph of cosine similarity between given player and all other players
    at listed position vs. their WAR/162 differential.
- `similarities`: File records related to embedding similarity generated by `get_similar_words`,
  `get_similar_players`, and `categorize_similar_words` in `embeddings.py`, as well as 
  `get_keyword_similarity` in `stat_plots.py`.
  - `keyword_sim.json`: Similarity scores between each word plotted in `plot_stats.py` and all players 
    in player set (see [`data/player_list.txt`](../data/player_list.txt)).
  - `player_word_stats.tsv`: Count of each word category represented in a player's top 10 words from `similar_words.json`.
  - `similar_players.json`: Top 10 most similar players for each player.
  - `similar_words.json`: Top 10 most similar words from interest set (see [`data/target_words.json`](../data/target_words.json)) for each player.
  - `similar_words_{category}.json`: Top 10 most similar words from specific category in interest set for each player.
